The default initial capacity of a HashMap is 16, and its capacity is defined as the number of buckets (slots) in the underlying array used to store data.
The 4 Core MetricsCapacity: 
Total bucket slots available in the internal array.
Size: Number of key-value pairs currently stored in the map.
Load Factor: Threshold ratio determining when to resize (Default: 0.75).
Resize Threshold: The exact size target triggering a growth phase (Capacity × Load Factor). 75%

Before Java 8: Buckets used a pure LinkedList. If multiple keys hashed to the same bucket (a collision), they were appended to the list. Performance was \(O(N)\) for lookups in that bucket.
Java 8 and Newer: To prevent performance degradation, if a single bucket grows to hold 8 elements (called the TREEIFY_THRESHOLD), Java automatically converts that bucket's LinkedList into a Red-Black Tree. This improves lookup performance to \(O(\log N)\)

Streams:
Introduced in Java 8, the Stream API (java.util.stream) is a pipeline framework for processing collections of data declaratively. Instead of writing nested loops and conditional blocks (imperative style), you write what you want to achieve (functional style).A Stream is not a data structure—it does not store data. Instead, it carries data from a source (like a Collection, Array, or I/O channel) through a pipeline of operations.
3 pipeline steps: Source → Intermediate Operations → Terminal Operation. 
[Collection] ──> Stream() ──> Filter() ──> Map() ──> Collect()
  (Source)                     (Intermediate)          (Terminal)

Here is that exact same breakdown style for every single tag in your pom.xml file.
## 1. The Identity Tags

* <project>
In Maven, the <project> tag acts as the master container that wraps your entire configuration file from start to finish, telling the system that this XML document is a project blueprint.
* <modelVersion>
In Maven, the <modelVersion> tag defines the layout version of the POM file structure itself, ensuring that Maven knows exactly how to read and interpret the tags inside.
* <groupId>
In Maven, the <groupId> tag specifies the unique identifier or package name of your organization, preventing your project from conflicting with code written by other companies.
* <artifactId>
In Maven, the <artifactId> tag defines the official name of your specific project, which becomes the final name of the JAR or WAR file you generate.
* <version>
In Maven, the <version> tag marks the current development edition or release number of your application, showing whether the code is a stable release or a work-in-progress.

## 2. The Settings Tags

* <properties>
In Maven, the <properties> tag acts as a central control panel where you define global variables, allowing you to change version numbers or settings across the whole file in one place.
* <maven.compiler.source>
In Maven, the <maven.compiler.source> tag tells the system which version of Java you used to write your code, ensuring modern features like Streams are recognized.
* <maven.compiler.target>
In Maven, the <maven.compiler.target> tag defines the Java version that the final compiled code must be compatible with so it runs smoothly on the target machine.
* <project.build.sourceEncoding>
In Maven, the <project.build.sourceEncoding> tag forces a specific text encoding standard (usually UTF-8) to prevent text glitches or weird symbol errors across different computers.

## 3. The Dependency Tags

* <dependencies>
In Maven, the <dependencies> tag acts as a shopping cart container that holds the list of all external libraries and frameworks your application needs to download from the internet.
* <dependency>
In Maven, the <dependency> tag declares a single, specific external tool or library (like Lombok) that your project requires to compile and function.
* <scope>
In Maven, the <scope> tag restricts exactly when an external dependency is allowed to be used, such as limiting a testing tool strictly to your test phases.

## 4. The Build & Plugin Tags

* <build>
In Maven, the <build> tag tells Java exactly how to compile, pack, and configure your application during the build process.
* <plugins>
In Maven, the <plugins> tag serves as a toolbox container within the build process, holding all the custom extensions and automated tools you want to run.
* <plugin>
In Maven, the <plugin> tag sets up a specific automated task or extra compiler tool (like the compiler plugin) to execute a specialized job during assembly.
* <configuration>
In Maven, the <configuration> tag passes specific custom settings and rules directly to a plugin, fine-tuning exactly how that tool behaves during the build.
